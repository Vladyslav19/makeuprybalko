# Бот запису на макіяж (Telegram + Google Sheets)

Telegram-бот на Node.js (Telegraf), який приймає записи клієнтів на макіяж,
зберігає розклад і записи в Google Таблиці, надсилає повідомлення майстру про
нові записи, нагадування клієнтам перед візитом, і дає майстру адмін-панель
прямо в боті.

## Можливості

- Клієнт: `/book` → вибір послуги → вибір дати → вибір часу → ім'я/телефон →
  підтвердження.
- Майстер отримує повідомлення про кожен новий запис і про скасування.
- Клієнту приходить нагадування за N годин до візиту (за замовчуванням 24).
- Адмін-панель майстра прямо в боті: послуги, слоти (вільний час), список
  записів з можливістю скасування.
- Усі дані — у звичайній Google Таблиці, можна дивитись і правити руками.

## 1. Що потрібно підготувати

1. Акаунт Telegram і бот, створений через **@BotFather** (команда `/newbot`).
   Збережіть токен виду `123456789:AA...`.
2. Свій Telegram chat_id — дізнатися можна у **@userinfobot** (напишіть йому
   `/start`, він надішле ваш ID). Це буде `ADMIN_CHAT_ID`.
3. Google-акаунт для Google Таблиці.
4. Акаунт на [GitHub](https://github.com) і на [Render](https://render.com)
   (безкоштовно) — для хостингу.
5. Акаунт на [cron-job.org](https://cron-job.org) або
   [UptimeRobot](https://uptimerobot.com) (безкоштовно) — щоб бот не "засинав"
   і нагадування приходили вчасно.

## 2. Налаштування Google Таблиці

1. Створіть нову Google Таблицю (sheets.new). Назва вкладок не важлива —
   бот сам створить вкладки `Services`, `Slots`, `Bookings` при першому запуску.
2. Скопіюйте ID таблиці з адресного рядка:
   `https://docs.google.com/spreadsheets/d/ЦЕЙ_ID/edit` → це `SHEET_ID`.
3. Зайдіть у [Google Cloud Console](https://console.cloud.google.com/):
   - Створіть новий проєкт (або використайте наявний).
   - У розділі **APIs & Services → Library** увімкніть **Google Sheets API**.
   - У розділі **APIs & Services → Credentials** натисніть **Create
     Credentials → Service Account**, задайте будь-яке ім'я, створіть.
   - Відкрийте створений сервісний акаунт → вкладка **Keys** → **Add Key →
     Create new key → JSON**. Завантажиться файл `*.json`.
4. У завантаженому JSON знайдіть поля `client_email` і `private_key` — це
   `GOOGLE_SERVICE_ACCOUNT_EMAIL` і `GOOGLE_PRIVATE_KEY`.
5. Відкрийте вашу Google Таблицю → кнопка **"Налаштування доступу" (Share)** →
   додайте email з `client_email` з правами **Редактор (Editor)**.

## 3. Локальний запуск (перевірка перед деплоєм)

```bash
cd makeup-booking-bot
npm install
cp .env.example .env
```

Відкрийте `.env` і заповніть:
- `BOT_TOKEN` — токен від BotFather
- `ADMIN_CHAT_ID` — ваш chat_id
- `SHEET_ID` — ID таблиці
- `GOOGLE_SERVICE_ACCOUNT_EMAIL` і `GOOGLE_PRIVATE_KEY` — з JSON-ключа
  (приватний ключ вставляйте одним рядком, переноси рядків як `\n`)
- `PUBLIC_URL` залиште порожнім для локального запуску — бот працюватиме
  через long polling

Запуск:

```bash
npm run dev
```

Напишіть боту `/start`, потім `/admin` (з акаунта, чий chat_id вказано як
`ADMIN_CHAT_ID`) і додайте першу послугу та слот:

```
/addservice Денний макіяж;60;1000
/addslot 10.08.2026 14:00
```

Потім з іншого акаунта (або того ж) надішліть `/book` і пройдіть запис.

## 4. Безкоштовний хостинг на Render

1. Завантажте папку проєкту в новий репозиторій на GitHub (без файлу `.env` —
   він у `.gitignore`).
2. На [render.com](https://render.com) → **New → Web Service** → підключіть
   репозиторій.
3. Налаштування сервісу:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free
4. У розділі **Environment** додайте всі змінні з `.env` (крім `PUBLIC_URL` —
   його додасте на наступному кроці) — `BOT_TOKEN`, `ADMIN_CHAT_ID`,
   `SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`,
   `REMINDER_HOURS_BEFORE`, `CRON_SECRET`.
   Приватний ключ вставляйте як є, з `\n` всередині одного рядка (без зайвих
   лапок навколо).
5. Розгорніть сервіс. Render видасть публічну адресу виду
   `https://ваш-сервіс.onrender.com`.
6. Додайте змінну `PUBLIC_URL` = ця адреса (без слеша в кінці) і
   перезбережіть/перезапустіть сервіс (Manual Deploy або Restart).
   Після цього бот сам встановить webhook при старті.
7. Перевірте, що бот відповідає в Telegram.

**Важливо про безкоштовний тариф Render:** сервіс "засинає" приблизно через
15 хвилин без запитів і прокидається ~30-60 секунд на перше повідомлення. Це
нормально для бота на старті: клієнт один раз почекає відповідь довше. Щоб і
тримати сервіс "у тонусі", і не пропускати нагадування клієнтам, налаштуйте
зовнішній пінг — крок 5.

## 5. Налаштування зовнішнього пінгу (тримає бота "живим" + шле нагадування)

1. Зареєструйтесь на [cron-job.org](https://cron-job.org) або
   [UptimeRobot](https://uptimerobot.com).
2. Створіть нову задачу/монітор:
   - **URL:** `https://ваш-сервіс.onrender.com/reminders/run?secret=ЗНАЧЕННЯ_CRON_SECRET`
     (використовуйте те саме значення, що задали у змінній `CRON_SECRET`)
   - **Періодичність:** кожні 10–15 хвилин
3. Збережіть. Тепер кожні 10-15 хвилин Render отримуватиме запит — сервіс не
   буде довго засинати, а бот на кожен такий пінг перевірятиме, кому пора
   надіслати нагадування про візит.

Якщо безкоштовний "сон" Render все одно завдає незручностей (затримка першої
відповіді клієнту), розгляньте варіант тримати бота на власній завжди
увімкненій машині/VPS через `pm2` — тоді режим `PUBLIC_URL` можна взагалі не
використовувати і запускати через long polling (`npm start` без `PUBLIC_URL`
у `.env`).

## 6. Як користуватись (для майстра)

- `/admin` — список усіх адмін-команд
- `/addservice Назва;Тривалість_хв;Ціна` — додати послугу
- `/services` — список послуг
- `/delservice Назва` — видалити послугу
- `/addslot ДД.ММ.РРРР ГГ:ХХ` — відкрити один слот для запису
- `/addslots ДД.ММ.РРРР ГГ:ХХ_початок ГГ:ХХ_кінець` — одразу відкрити діапазон
  слотів з кроком `SLOT_INTERVAL_MINUTES` (наприклад,
  `/addslots 10.08.2026 10:00 18:00` створить слоти 10:00, 10:30, 11:00 ... 17:30)
- `/slots` — список вільних слотів
- `/delslot ДД.ММ.РРРР ГГ:ХХ` — закрити слот
- `/bookings` — список записів з кнопкою скасування

### Як працює бронювання послуг довших за один слот

Слоти — це "кубики" фіксованої довжини (за замовчуванням 30 хв, змінюється
через `SLOT_INTERVAL_MINUTES`). Коли клієнт обирає послугу тривалістю, скажімо,
90 хв, бот сам шукає 3 вільні слоти підряд (30+30+30) і показує клієнту лише ті
варіанти часу початку, де таких слотів підряд справді вистачає. При
підтвердженні запису бот займає всі потрібні слоти одразу, а при скасуванні —
звільняє їх усі. Тому додавайте слоти через `/addslot` або `/addslots` саме з
кроком, вказаним у `SLOT_INTERVAL_MINUTES` (за замовчуванням кожні 30 хв) —
інакше пошук послідовних вільних слотів під довгі послуги працюватиме
некоректно.

## 7. Як користуватись (для клієнта)

- `/start` — привітання і меню
- `/book` (або кнопка «📅 Записатися») — запис на візит
- `/mybookings` — свої записи
- `/cancelbooking` — скасувати свій запис

## Структура проєкту

```
makeup-booking-bot/
  src/
    index.js              — точка входу, express-сервер, webhook/polling
    config.js              — читання змінних середовища
    sheets.js               — робота з Google Sheets (послуги, слоти, записи)
    reminders.js            — перевірка і надсилання нагадувань
    scenes/bookingWizard.js — покроковий діалог запису клієнта
    handlers/client.js      — команди клієнта
    handlers/admin.js       — команди майстра (адмін-панель)
  package.json
  .env.example
```

## Обмеження / що можна покращити далі

- Усі дані зберігаються в Google Sheets — при дуже великому потоці записів
  (сотні на день) варто перейти на справжню БД (Postgres тощо).
- Внутрішньопроцесна сесія Telegraf скидається при перезапуску сервісу —
  якщо клієнт не встиг завершити `/book` до рестарту, доведеться почати
  заново.
- Часовий пояс окремо не враховується — час у таблиці інтерпретується як
  локальний час сервера. Якщо це важливо, можна закріпити `TZ` у змінних
  середовища Render.

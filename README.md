# Бот записи на макияж (Telegram + Google Sheets)

Telegram-бот на Node.js (Telegraf), который принимает записи клиентов на макияж,
хранит расписание и записи в Google Таблице, шлёт уведомления мастеру о новых
записях, напоминания клиентам перед визитом, и даёт мастеру админ-панель прямо
в боте.

## Возможности

- Клиент: `/book` → выбор услуги → выбор даты → выбор времени → имя/телефон →
  подтверждение.
- Мастер получает сообщение о каждой новой записи и об отменах.
- Клиенту приходит напоминание за N часов до визита (по умолчанию 24).
- Админ-панель мастера прямо в боте: услуги, слоты (свободное время), список
  записей с возможностью отмены.
- Все данные — в обычной Google Таблице, можно смотреть и править руками.

## 1. Что нужно подготовить

1. Аккаунт Telegram и бот, созданный через **@BotFather** (команда `/newbot`).
   Сохраните токен вида `123456789:AA...`.
2. Свой Telegram chat_id — узнать можно у **@userinfobot** (напишите ему
   `/start`, он пришлёт ваш ID). Это будет `ADMIN_CHAT_ID`.
3. Google-аккаунт для Google Таблицы.
4. Аккаунт на [GitHub](https://github.com) и на [Render](https://render.com)
   (бесплатно) — для хостинга.
5. Аккаунт на [cron-job.org](https://cron-job.org) (бесплатно) — чтобы бот не
   "засыпал" и напоминания приходили вовремя.

## 2. Настройка Google Таблицы

1. Создайте новую Google Таблицу (sheets.new). Название вкладок не важно —
   бот сам создаст вкладки `Services`, `Slots`, `Bookings` при первом запуске.
2. Скопируйте ID таблицы из адресной строки:
   `https://docs.google.com/spreadsheets/d/ЭТОТ_ID/edit` → это `SHEET_ID`.
3. Зайдите в [Google Cloud Console](https://console.cloud.google.com/):
   - Создайте новый проект (или используйте существующий).
   - В разделе **APIs & Services → Library** включите **Google Sheets API**.
   - В разделе **APIs & Services → Credentials** нажмите **Create Credentials
     → Service Account**, задайте любое имя, создайте.
   - Откройте созданный сервисный аккаунт → вкладка **Keys** → **Add Key →
     Create new key → JSON**. Скачается файл `*.json`.
4. В скачанном JSON найдите поля `client_email` и `private_key` — это
   `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_PRIVATE_KEY`.
5. Откройте вашу Google Таблицу → кнопка **"Настройки доступа" (Share)** →
   добавьте email из `client_email` с правами **Редактор (Editor)**.

## 3. Локальный запуск (проверка перед деплоем)

```bash
cd makeup-booking-bot
npm install
cp .env.example .env
```

Откройте `.env` и заполните:
- `BOT_TOKEN` — токен от BotFather
- `ADMIN_CHAT_ID` — ваш chat_id
- `SHEET_ID` — ID таблицы
- `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_PRIVATE_KEY` — из JSON-ключа
  (приватный ключ вставляйте одной строкой, переносы строк как `\n`)
- `PUBLIC_URL` оставьте пустым для локального запуска — бот будет работать
  через long polling

Запуск:

```bash
npm run dev
```

Напишите боту `/start`, затем `/admin` (с аккаунта, чей chat_id указан как
`ADMIN_CHAT_ID`) и добавьте первую услугу и слот:

```
/addservice Дневной макияж;60;2500
/addslot 10.08.2026 14:00
```

Затем с другого аккаунта (или того же) отправьте `/book` и пройдите запись.

## 4. Бесплатный хостинг на Render

1. Загрузите папку проекта в новый репозиторий на GitHub (без файла `.env` —
   он в `.gitignore`).
2. На [render.com](https://render.com) → **New → Web Service** → подключите
   репозиторий.
3. Настройки сервиса:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free
4. В разделе **Environment** добавьте все переменные из `.env` (кроме
   `PUBLIC_URL` — его добавите на следующем шаге) — `BOT_TOKEN`,
   `ADMIN_CHAT_ID`, `SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`,
   `GOOGLE_PRIVATE_KEY`, `REMINDER_HOURS_BEFORE`, `CRON_SECRET`.
   Приватный ключ вставляйте как есть, с `\n` внутри одной строки.
5. Разверните сервис. Render выдаст публичный адрес вида
   `https://ваш-сервис.onrender.com`.
6. Добавьте переменную `PUBLIC_URL` = этот адрес (без слэша в конце) и
   пересоберите/перезапустите сервис (Manual Deploy или Restart).
   После этого бот сам установит webhook при старте.
7. Проверьте, что бот отвечает в Telegram.

**Важно про бесплатный тариф Render:** сервис "засыпает" примерно через 15
минут без запросов и просыпается ~30-60 секунд на первое сообщение. Это
нормально для бота на старте: клиент один раз подождёт ответ подольше. Чтобы
и держать сервис "в тонусе", и не пропускать напоминания клиентам, настройте
внешний пинг — шаг 5.

## 5. Настройка cron-job.org (держит бота "живым" + шлёт напоминания)

1. Зарегистрируйтесь на [cron-job.org](https://cron-job.org).
2. Создайте новую задачу (Create cronjob):
   - **URL:** `https://ваш-сервис.onrender.com/reminders/run?secret=ЗНАЧЕНИЕ_CRON_SECRET`
     (используйте то же значение, что задали в переменной `CRON_SECRET`)
   - **Периодичность:** каждые 10–15 минут
3. Сохраните. Теперь каждые 10-15 минут Render будет получать запрос — сервис
   не будет засыпать надолго, а бот на каждый такой пинг будет проверять, кому
   пора отправить напоминание о визите.

Если бесплатный "сон" Render всё равно доставляет неудобства (задержка первого
ответа клиенту), рассмотрите вариант держать бота на своей всегда включённой
машине/VPS через `pm2` — тогда режим `PUBLIC_URL` можно не использовать вовсе
и запускать через long polling (`npm start` без `PUBLIC_URL` в `.env`).

## 6. Как пользоваться (для мастера)

- `/admin` — список всех админ-команд
- `/addservice Название;Длительность_мин;Цена` — добавить услугу
- `/services` — список услуг
- `/delservice Название` — удалить услугу
- `/addslot ДД.ММ.ГГГГ ЧЧ:ММ` — открыть слот для записи
- `/slots` — список свободных слотов
- `/delslot ДД.ММ.ГГГГ ЧЧ:ММ` — закрыть слот
- `/bookings` — список записей с кнопкой отмены

## 7. Как пользоваться (для клиента)

- `/start` — приветствие и меню
- `/book` (или кнопка «📅 Записаться») — запись на визит
- `/mybookings` — свои записи
- `/cancelbooking` — отменить свою запись

## Структура проекта

```
makeup-booking-bot/
  src/
    index.js              — точка входа, express-сервер, webhook/polling
    config.js              — чтение переменных окружения
    sheets.js               — работа с Google Sheets (услуги, слоты, записи)
    reminders.js            — проверка и отправка напоминаний
    scenes/bookingWizard.js — пошаговый диалог записи клиента
    handlers/client.js      — команды клиента
    handlers/admin.js       — команды мастера (админ-панель)
  package.json
  .env.example
```

## Ограничения / что можно улучшить дальше

- Все данные хранятся в Google Sheets — при очень большом потоке записей
  (сотни в день) стоит перейти на настоящую БД (Postgres и т.п.).
- Внутрипроцессная сессия Telegraf сбрасывается при перезапуске сервиса —
  если клиент не успел закончить `/book` до рестарта, придётся начать заново.
- Часовой пояс не учитывается отдельно — время в таблице интерпретируется как
  локальное время сервера. Если это важно, можно закрепить `TZ` в переменных
  окружения Render.
